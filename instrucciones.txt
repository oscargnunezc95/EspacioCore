Necesitamos automatizar por completo el "Motor de Ciclo de Vida y Morosidad" de nuestro SaaS (estadoPrisma) mediante un comando programado (Cron Job) y blindar la lógica de fechas para evitar que los pagos atrasados regalen días gratis de servicio.

TU TAREA EN 5 PASOS (Ejecuta y sobrescribe directamente):

1. REFINAR EL MOTOR EN EL MODELO (`app/Models/Studio.php`)
Asegúrate de que el método público `checkAndManageLifecycle(): void` maneje el corte de guillotina llamando a la API de Mercado Pago:

- REGLA 1: TRANSICIÓN DE PLANES VENCIDOS (Suscripción expirada naturalmente)
  Si `subscription_expires_at` ya pasó (`isPast()`) y el `subscription_status` NO es 'past_due' ni 'free':
  - Si existe un `next_plan_id`:
    - Si el plan destino es 'free': `subscription_plan_id = next_plan_id`, `next_plan_id = null`, `subscription_status = 'free'`, `subscription_expires_at = now()->addYears(100)`, `mp_preapproval_id = null`.
    - Si el plan destino es de pago (Upgrade diferido): `subscription_plan_id = next_plan_id`, `next_plan_id = null`, `subscription_status = 'pending_payment'`.
  - Si NO existe un `next_plan_id`, por seguridad pásalo al plan 'free' con sus flags por defecto.

- REGLA 2: LÍMITE DE MOROSIDAD (Los 5 días de gracia)
  Si el `subscription_status === 'past_due'`:
  - Evalúa si pasaron más 5 días: `now()->diffInDays($this->subscription_expires_at) > 5`.
  - Si se cumple:
    1. CANCELACIÓN INVERSA POR API: Si tiene `mp_preapproval_id`, ejecuta:
       `try { app(\App\Services\MercadoPagoService::class)->cancelPreapproval($this->mp_preapproval_id); } catch (\Exception $e) { Log::error("Error cancelando MP por morosidad: " . $e->getMessage()); }`
    2. DOWNGRADE FORZADO: Busca el ID del plan 'free' y actualiza el estudio: `subscription_plan_id = $freePlanId`, `subscription_status = 'free'`, `subscription_expires_at = now()->addYears(100)`, `mp_preapproval_id = null`, `next_plan_id = null`.
    3. Deja un `Log::info("Estudio ID {$this->id} movido a plan gratuito por superar los 5 días de morosidad.");`

2. CORREGIR EL ANCLAJE DEL CICLO DE FACTURACIÓN (`app/Services/MercadoPagoService.php`)
En el método que procesa pagos exitosos del SaaS (donde actualizas el estado tras recibir el topic `payment` y guardas en `saas_payments`):
- Al actualizar el `subscription_expires_at` del estudio, NUNCA uses `now()->addMonth()` a ciegas.
- Si el pago es exitoso tras un reintento por morosidad, debes mantener el ciclo original. Implementa esta lógica matemática:
  `$newExpiration = ($studio->subscription_expires_at && $studio->subscription_status !== 'free' && $studio->subscription_expires_at->isPast()) ? $studio->subscription_expires_at->addDays(30) : now()->addDays(30);`
- Si la suscripción estaba 'past_due', devuélvela a su estado normal (el slug del plan actual).

3. CREAR EL COMANDO ARTISAN (`app/Console/Commands/CleanExpiredSubscriptions.php`)
- Signature: `saas:clean-subscriptions`
- Description: `Procesa expiraciones y bloqueos por morosidad de más de 5 días de forma masiva.`
- En el método `handle()`: Busca los estudios evaluables:
  `Studio::where('subscription_status', 'past_due')->orWhere(function($q) { $q->where('subscription_expires_at', '<=', now())->where('subscription_status', '!=', 'free'); })->get();`
  Recórrelos y ejecuta: `$studio->checkAndManageLifecycle();`

4. REGISTRAR EL CRON JOB EN EL PLANIFICADOR (`routes/console.php`)
Registra el comando para que corra todos los días a la medianoche:
`use Illuminate\Support\Facades\Schedule;`
`Schedule::command('saas:clean-subscriptions')->daily();`

5. REFORZAR EL WEBHOOK PARA MOROSIDAD (`app/Services/MercadoPagoService.php` y `app/Mail/SubscriptionPastDueMail.php`)
- Genera el mailable `SubscriptionPastDueMail` con diseño Zinc.
- En el método `processSaaSSubscription()`, si el estado enviado por Mercado Pago es 'pending' o 'past_due':
  - Actualiza el `subscription_status` del estudio a 'past_due'. (NO modifiques su `subscription_expires_at`).
  - Despacha el correo a la cola: `Mail::to($studio->user->email)->queue(new \App\Mail\SubscriptionPastDueMail($studio));`
